Introduction

The ScrollSpy module is a powerful tool for creating interactive navigation experiences that respond to the user's scroll position. It automatically highlights navigation items as their corresponding content sections come into view.

Key Benefit: ScrollSpy uses the modern IntersectionObserver API for efficient, performant scroll tracking without relying on scroll event listeners.

This approach provides better performance than traditional scroll listeners, especially on pages with many elements or complex layouts. The module handles all the complexity of tracking multiple sections and updating navigation states.

Features

ScrollSpy comes packed with features designed to make navigation tracking simple and efficient:

  • Automatic Highlighting: Navigation items are automatically highlighted when their corresponding sections enter the viewport
  • IntersectionObserver API: Uses modern browser APIs for optimal performance
  • Customizable Margins: Configure viewport margins to account for fixed headers or other UI elements
  • Callback Support: Execute custom code when sections become active
  • Single Active State: Only one navigation item is active at a time
  • Smooth Scroll Integration: Works seamlessly with smooth scrolling
The default rootMargin is set to '-55px 0px -85%' which accounts for typical fixed header heights and ensures sections become active when they're prominently visible in the viewport.

These features combine to create a robust navigation system that enhances user experience by providing clear visual feedback about the current page position. The module is designed to work out of the box with minimal configuration.

Usage

Getting started with ScrollSpy is straightforward. Here's a basic example:

import { Application, ScrollSpy } from 'jupiter' const app = new Application() const scrollSpy = new ScrollSpy(app, { onIntersect: (target, trigger) => { console.log('Section active:', target.id) } })

The HTML structure requires two data attributes:

  • data-scrollspy-trigger - Applied to content sections you want to track
  • data-scrollspy-target - Applied to navigation links that should be highlighted
<!-- Navigation link --> <a href="#section1" data-scrollspy-target="section1"> Section 1 </a> <!-- Content section --> <section id="section1" data-scrollspy-trigger="section1"> <h2>Section 1</h2> <p>Content here...</p> </section>

The module automatically manages the 'active' class on navigation items as you scroll through the page. You can customize this behavior through CSS by styling the .active class according to your design needs.

Configuration

ScrollSpy accepts configuration options to customize its behavior:

new ScrollSpy(app, { // Callback executed when a section becomes active onIntersect: (target, trigger) => { // target: the content section element // trigger: the navigation link element console.log('Active section:', target.id) } })
IntersectionObserver Configuration: The module uses a rootMargin of '-55px 0px -85%' by default. This means:
  • Top margin: -55px (accounts for fixed header)
  • Bottom margin: -85% (triggers when section is in upper portion of viewport)

The rootMargin values can be adjusted by modifying the module source if you need different trigger points. The current configuration works well for most single-column layouts with fixed headers around 50-60px tall.

The onIntersect callback receives two parameters: the target element (content section) and the trigger element (navigation link). This allows you to implement custom behavior like analytics tracking, URL updates, or additional UI changes.

API Reference

Complete API documentation for the ScrollSpy module:

Constructor

new ScrollSpy(app, options)
  • app (Application) - Jupiter Application instance
  • options (Object) - Configuration options
  • options.onIntersect (Function) - Callback when section becomes active

Data Attributes

data-scrollspy-trigger="unique-id" // On content sections data-scrollspy-target="unique-id" // On navigation links

CSS Classes

  • .active - Applied to navigation items when their section is visible

Methods

The module is initialized once and handles all updates automatically through the IntersectionObserver. No manual method calls are required during normal usage.
